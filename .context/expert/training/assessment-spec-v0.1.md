# Публичная спецификация входной диагностики iOS-Эксперта v0.1

Статус: `DESIGN_ONLY_NO_HIDDEN_TASKS`

Этот файл определяет, ЧТО и КАК проверяется. Конкретные итоговые/скрытые задачи здесь запрещены.

## Проверяемые семейства
1. Secure boot/recovery: построить причинную цепочку по новым данным и указать границы доказанного.
2. XNU: локализовать симптом по подсистемам Mach/BSD/VM/IPC/process lifecycle на неизвестном ранее случае.
3. IOKit: по DeviceTree/IORegistry evidence различить availability, provider publication, matching, probe/start и конечную регистрацию устройства.
4. APFS: сформировать несколько конкурирующих гипотез root-mount failure и выбрать следующий наименее разрушительный discriminator.
5. Code signing/runtime policy: отличить signature structure, trust/policy, entitlement и loader/runtime ограничения.
6. launchd/dyld: локализовать ранний userland failure без приписывания причины ядру без доказательств.
7. Evidence discipline: привязать каждый вывод к версии/источнику, явно отметить неизвестность и не расширять применимость без проверки.

## Формат
- E1: объяснение + применение к новому примеру;
- E2: практический read-only анализ;
- E3: новая комбинация условий;
- E4: интеграционная диагностика полной цепочки.

## Заранее фиксируемые критерии
- корректная локализация первого доказанного отказа;
- отсутствие необоснованной причинности;
- использование нескольких независимых свидетельств там, где это необходимо;
- сохранение противоречий и неизвестностей;
- выбор минимально вмешивающегося следующего эксперимента;
- корректное разграничение документированного и эмпирического поведения;
- отсутствие переноса результата за проверенную область.

## Независимость
Конкретный `assessment-instance` должен быть создан вне readable-history обучающего контура. До доказательства реального разделения доступа итоговая аттестация остаётся `BLOCKED`; допускается только формирующая/мысленная проверка.
