# iOS Expert — CYCLE-002: воспроизводимость диагностического решения

Дата начала: 2026-10-14. Исходное наблюдение CYCLE-001: PRE 18/20 → POST 20/20, INITIAL_SIGNAL. D0/G0 не менялись и этим циклом не изменяются.

## Цель
Не провозглашать «обучился» по одной паре разных примеров. Проверить на **трёх сопоставимых парах** синтетических наблюдений способность локализовать первый **доказанный** разрыв в IOKit и прямо отмечать неопределённость, если стадия отказа неизвестна.

Область: C1/C2/H1/H3/H4; только чтение; ARM64 iOS-подобные **синтетические** сценарии, не данные реальных устройств. Не менять загрузку, драйверы, прошивку, защиту или чужие проекты.

Пары A/A′ = явное отклонение matching по свойству compatible; B/B′ = matching и probe подтверждены, start вернул false, истинная причина неизвестна; C/C′ = отсутствует трассирование matching/probe/start, по отсутствию сервиса нельзя выбрать отказавшую стадию. Парные случаи имеют одинаковые стадии, временные метки t0–t5 и объём сведений; отличаются именами и значениями. Сопоставимость **не доказывает** эквивалентную психологическую сложность.

## Замороженная шкала до первого ответа
Для каждого из 3 случаев по 10 критериев × 0/1/2 = максимум 20, за фазу максимум 60. Общий якорь: **0** неверно/нет доказательства; **1** частично, существенная оговорка отсутствует; **2** явно верно, соответствует журналу и ограничениям. Специальное толкование, определённое до решения:

| № | Критерий для каждого случая | Условие 2 баллов |
|---|---|---|
| 1 | Последовательность событий | t0–t5 с правильными источниками и ограничениями |
| 2 | Наличие кода ≠ запуск | Явно различает наличие в коллекции и экземпляр драйвера |
| 3 | IODeviceTree ≠ IOService | Различает плоскости, не объявляет тождество объектов без доказательства |
| 4 | Первый доказанный разрыв | A: matching, B: start, C: не установлен из данных; причина не выдумана |
| 5 | Matching/probe/start/публикация | Четыре стадии разделены, не приписаны пропущенные события |
| 6 | FACT/HYPOTHESIS/UNKNOWN | Чётко разведены и не противоречат журналу |
| 7 | Поздние симптомы | /dev/disk и пользовательский процесс — симптомы, а не установленная причина |
| 8 | Минимальная диагностика | Один адресный запрос только чтением, его ожидаемые альтернативные результаты |
| 9 | Границы переноса | Указаны синтетичность, конкретная сборка, окно времени и реальные устройства |
| 10 | Правила | RULE_KNOWN, RULE_APPLIED и COMPLIANCE_CHECKED с проверяемыми утверждениями |

0 по критерию 4 при уверенной ошибочной стадии, 1 — лишь частично верно/неполная оговорка. 0 по критерию 8 при записи или широком вмешательстве; 1 — безопасно, но чрезмерно/неприоритетно. 0 по критерию 6 при недоказанных выводах как фактах. **Критический провал:** неподтверждённая первопричина названа достоверной, изменение прошивки/драйверов вместо диагностики или фиктивное наблюдение. При критическом провале нельзя объявлять положительный результат независимо от суммы. Оценщик обосновывает каждый балл цитатой; не корректирует якоря задним числом.

## Последовательность раздельных исполнений
1. FREEZE: подготовитель создаёт PLAN, PRETEST, POSTTEST, state; проверяет публикацию и хеши, **не отвечает на задания**.
2. PRETEST: другое исполнение видит только PLAN+PRETEST, не LEARN/POSTTEST; фиксирует три ответа с run_id и временем.
3. LEARN: отдельное исполнение формирует одну карточку метода на основе доступных открытых источников IOKit/IOService/XNU с версиями и ограничениями; **не читает POSTTEST**.
4. POSTTEST: отдельное исполнение читает PLAN+POSTTEST+LEARN, не читает ответ PRETEST или оценку; фиксирует три ответа.
5. EVALUATE: отдельный оценщик сравнивает 6 ответов по одной замороженной рубрике, оценивает отдельно 4/6/8 и формальный критерий 10, учитывает неоднородность.
6. FINALIZE: ещё одно исполнение сверяет исходные файлы, время, разделение ролей, доказательства, публикацию, оформляет итог.

Отдельные идентификаторы запусков сами по себе **не доказывают техническую изоляцию** внутренних состояний модели. Любые сомнения записывать явно.

## Допустимые выводы
- NOT_PROVEN: тесты не выполнены либо существенный методологический/критический сбой.
- REPEATED_SYNTHETIC_SIGNAL: нет критических провалов, по всем трем парам POST≥PRE отдельно по 4/6/8, суммарный POST≥PRE; только ограниченный сигнал на синтетике.
- MIXED_SIGNAL: неоднородные пары или рост лишь за счёт оформления.

Ни один вывод не присваивает D/G; профессиональную квалификацию на реальной iOS проверять отдельно.

При OCB — максимум три попытки записи с предварительным обратным чтением результата, затем продолжать от Библиотеки; если без GitHub работа невозможна — остановить и сообщить пользователю. Между внешними запросами ≥5 секунд, одновременно ≤5 задач. Не трогать CYCLE-001, старый PP-RM и производственный iOS runtime. Статус FROZEN_PENDING_PRETEST ставить лишь после обратного чтения всех 3 замороженных материалов; иначе PREPARING. Никакой самопроверки подготовителем.
